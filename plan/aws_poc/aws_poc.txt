PHASE 0 — Prep: Create S3 Bucket in Dev Account

Skip if already done from GCP POC.

0a. Create bucket

aws-okta exec dev-admin -- aws s3api create-bucket \
  --bucket vyom-test-cross-provider \
  --region us-west-2 \
  --create-bucket-configuration LocationConstraint=us-west-2

0b. Block public access

aws-okta exec dev-admin -- aws s3api put-public-access-block \
  --bucket vyom-test-cross-provider \
  --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

0c. Seed test file

echo 'hello cross-provider' | aws-okta exec dev-admin -- aws s3 cp - s3://vyom-test-cross-provider/test.txt
aws-okta exec dev-admin -- aws s3 ls s3://vyom-test-cross-provider/
# Expected: test.txt listed

aws-okta exec mist-admin -- aws sts assume-role \

Note the temp credentials ( AccessKeyId ,  SecretAccessKey ,  SessionToken )

AWS_SESSION_TOKEN=<from above> \

AWS_ACCESS_KEY_ID=<from above> \

PHASE 3 — Enable Access: Bucket Policy + IaC Apply

Two things must happen in parallel — both are required for cross-account access.

3a. Add bucket policy in dev account (allows staging role to read)

Create  bucket-policy.json :

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowCrossAccountReadRole",
            "Effect": "Allow",
            "Principal": {
                "AWS": "arn:aws:iam::660610034966:role/mistsys-staging-emr-ec2"
            },
            "Action": [
                "s3:GetObject",
                "s3:ListBucket"
            ],
            "Resource": [
                "arn:aws:s3:::vyom-test-cross-provider",
                "arn:aws:s3:::vyom-test-cross-provider/*"
            ]
        },
        {
            "Sid": "ForceSSLOnlyAccess",
            "Effect": "Deny",
            "Principal": "*",
            "Action": "s3:*",
            "Resource": "arn:aws:s3:::vyom-test-cross-provider/*",
            "Condition": {
                "Bool": {
                    "aws:SecureTransport": "false"
                }
            }
        }
    ]
}

Apply it:

aws-okta exec dev-admin -- aws s3api put-bucket-policy \
  --bucket vyom-test-cross-provider \
  --policy file://bucket-policy.json

Verify:

aws-okta exec dev-admin -- aws s3api get-bucket-policy \
  --bucket vyom-test-cross-provider \
  --query Policy --output text | python3 -m json.tool
# Expected: policy with mistsys-staging-emr-ec2 listed

3b. Apply IaC in aws-staging (attaches ctkb policy to the role)

cd aws-staging/auto/iam/emr-ec2
terragrunt apply

This creates and attaches  mistsys-staging-emr-ec2-ctkb-test  policy granting:

•  s3:List*  /  s3:Get*  on  vyom-test-cross-provider  in dev account

3c. Verify policy is now attached to the role

aws-okta exec mist-admin -- aws iam list-attached-role-policies \
  --role-name mistsys-staging-emr-ec2 \
  | grep ctkb
# Expected: "mistsys-staging-emr-ec2-ctkb-test" listed

aws-okta exec mist-admin -- aws iam get-role-policy \
  --role-name mistsys-staging-emr-ec2 \
  --policy-name mistsys-staging-emr-ec2-ctkb-test 2>/dev/null || \
aws-okta exec mist-admin -- aws iam list-attached-role-policies \
  --role-name mistsys-staging-emr-ec2

echo ""
